# Concept frames: the picture comes before the work

A model that sees its target hits it; a model that builds from words builds an average. Every scene, piece and screen in this studio has a picture it is built toward, generated by the studio itself, judged before it is used, and stored with the scene. This skill is how those pictures are made so that they are usable, not merely pretty.

## The tool

`python tools/assets/concept.py --slug <name> --subject "<prompt>" [--bible <style file>] [--pose tpose|apose] [--framing ...]` writes the image and a provenance record under `assets/refs/<slug>/`. It needs `OPENAI_API_KEY` in the environment; without it the tool prints the prompt it would send and exits, which is a blocker to report, not a reason to build without a target. The style bible is `game/VISION.md` plus the previous builds' side-by-sides; pass the frame of the previous scene as a reference image when the model accepts one, so the world stays one world.

## Four kinds of picture, four prompt shapes

**1. Target frame of a scene** — what the player sees. The prompt describes a gameplay screenshot, not concept art: the words that work are "in-game screenshot", "third person", the camera position and height, "Roblox-style blocky R15 character" when the player is in frame, a faint HUD (health bar top-left, objective text top-right), "no text elsewhere, no painterly brushwork, no concept-art framing". Describe the frame in planes (foreground, middle, far), the light (time of day, warm and cool sources), the palette, the one visual centre, and the density (what stands in every plane, so the frame is not empty). Wide aspect (21:9 or 16:9). What makes frames unusable: "buildable scale", "few pieces", "simple" in the prompt (the model obeys and returns a box world); asking for the whole city when the scene is one valley; leaving out the character's scale cue.

**2. Orthographic sheet of a piece** — what the modeller builds from. Four panels on one plain light-grey image: front, side, back, three-quarter, same scale, on a common ground line; even shadowless light; no background, no text, no perspective in the orthographic panels; crisp edges. Name the piece exactly as the kit will name it and describe its materials in the world's words. One sheet per piece type; a sheet for a family of variants shows the variants side by side.

**3. Single object for image-to-3D** — what Tripo receives. One object, nothing around it, plain flat light-grey background, three-quarter view from slightly above eye level, long lens so verticals stay parallel, even shadowless light, the whole object inside the frame with margin, square format. Only for organic or one-off objects (creatures, rocks, statues, a boat); never for a complex or a kit piece, which are modelled. The generated mesh is a form and scale guide the modeller builds over; its softness is not the studio's look.

**4. Interface mockup** — what the UI lane builds toward. A full-frame screenshot of the game with the interface as it should look at a named viewport (phone, tablet, desktop): the world from a target frame behind it, and the screen elements drawn on top in the world's palette: thin strokes, ornament from the world's culture, a display typeface for headings, the one element that reads first larger and brighter, every other element quieter. Describe each element and its state (a health bar at three quarters, an objective line, a prompt near a door, a dialogue box with a name plate). Words that work: "premium", "diegetic", "restrained", "console-quality"; words that fail: "modern", "clean", "minimal" alone (they produce a template).

## Judging a picture before it becomes a target

A fresh subagent sees the picture, `game/VISION.md` and the previous build's side-by-side, and answers only from the image: does it read as the same game as the previous builds; is there one visual centre; can each plane be built from kit pieces plus one hero; is the character's scale readable; is anything in it outside what the engine can render (volumetric forests, glass shaders, crowds of thousands); for sheets, are the panels truly orthographic and the same scale; for mockups, would a viewer call it a template. A picture that fails is regenerated with the finding written into the prompt, not used with a caveat.

## Keeping the world one world

Store every accepted picture under the scene (`game/scenes/<id>/target*.png`, `sheets/`, `ui/`), with its prompt in provenance. The next scene's prompts quote the palette, the materials and the signature details of the previous scene's accepted frame, and pass it as the reference image. When a lane changes something the frames depend on (a material, a proportion), the frames are regenerated before the next build, not patched in words.
